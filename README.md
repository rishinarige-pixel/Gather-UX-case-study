# Gather: Turning "we should hang out" into an actual plan

**A mobile app case study** · UX/UI Design · [Figma Project](https://www.figma.com/design/d6KH1O9Aw03wX2ZtBrFGSH/Gather) · [Prototype](https://www.figma.com/design/d6KH1O9Aw03wX2ZtBrFGSH/Gather?node-id=251-21329)

## The Problem

Making plans with friends usually dies in a group chat. Someone throws out an idea, like "anyone up for chai tonight?", and it gets buried under fifteen unrelated messages, a string of "maybe"s, and no one ever locks down a time or place. The idea just... evaporates.

**Gather** is a mobile app designed to solve that: a lightweight way for friend groups to float plans, gauge interest, and turn "maybe" into "yes, 7pm, that new spot," without the back and forth.

## The Solution

### Information Architecture
Before designing individual screens, I mapped out the full structure of the app: how Home, Plans, Calendar, and Profile relate to each other, and where every sub screen (filters, search, drafts, availability, etc.) lives within that structure.

[View the IA map in Figma](https://www.figma.com/design/d6KH1O9Aw03wX2ZtBrFGSH/Gather)

### Core User Flows
Three flows anchor the product experience:

**1. Posting a plan idea**
A friend opens the app, taps the compose button, types a loose idea, and optionally adds a time and visibility setting before posting. No pressure to lock in details up front.

**2. Reacting to a plan**
When a friend sees an idea land, they can respond with a single tap ("I'm in" or "Maybe") or suggest an alternate time, designed to lower the friction of committing.

**3. Confirming a plan**
Once enough friends have reacted, the original poster gets a nudge to "make it official." The app pre fills the details already gathered (time, interested friends) so confirming takes seconds, and a group chat spins up automatically.
